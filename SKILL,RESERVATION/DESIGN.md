# 오성학교 스킬·예약 작업 활동지 디자인 시스템

## 1. 문서 목적
강릉오성학교 교사가 AI 도구의 **스킬(Skill)** 과 **예약 작업(Scheduled task/action)** 을 처음 접해도 별도의 설명 없이 따라 할 수 있는 A4 실습 활동지를 제작한다. 기존 `ai-figma-workbook`의 단계형 활동지 구조와 시각 언어를 계승하되, 이번 자료의 내용과 페이지 구성은 새로 설계한다.

이 자료는 **2026년 10월 6일 기준, 개인 무료 계정에서 실제로 사용할 수 있는 기능을 중심으로 설명**한다. 기능 제공 범위는 계정·지역·순차 배포·제품 업데이트에 따라 달라질 수 있으므로, 메뉴가 보이지 않으면 사용자가 잘못한 것으로 단정하지 않는다.

## 2. 핵심 교육 메시지
### 2.1 세 개념을 먼저 구분한다
- **스킬 = HOW**  
  반복해서 사용할 작업 방법, 기준, 절차, 예시를 재사용 가능한 지침 묶음으로 만든다.
- **플러그인·앱·커넥터·MCP = WITH WHAT / WHERE**  
  AI가 외부 서비스, 데이터, 파일, 디자인 도구 등과 연결되어 할 수 있는 일을 확장한다.
- **예약 작업 = WHEN**  
  특정 시점이나 반복 주기에 AI 작업이 실행되도록 예약한다.

### 2.2 제품마다 같은 이름·같은 방식이 아니다
- Gemini는 ChatGPT·Claude와 같은 설치형 플러그인 체계보다 **Connected Apps 및 자체 연결 기능**을 중심으로 사용하므로, 이 활동지에서는 별도의 플러그인 설치 절차를 설명하지 않는다.
- ChatGPT 무료 계정은 이 활동지에서 다루는 **ChatGPT Skills 생성 기능의 대상이 아니다**. 대신 무료 계정에서 사용할 수 있는 범위의 예약 작업을 다룬다.
- Claude 무료 계정은 **Skills를 사용할 수 있지만 예약 작업은 무료 플랜 대상이 아니다**. 따라서 Claude는 스킬 만들기와 사용만 상세 안내한다.

## 3. 무료 기준 기능 지도
첫 페이지에 아래 표를 시각적으로 제시한다.

| 도구 | 스킬 | 외부 연결 | 예약 작업 | 이 활동지에서 상세 설명 |
|---|---|---|---|---|
| Gemini 무료 개인 계정 | 가능(순차 배포) | Connected Apps 방식 | 가능(순차 배포) | 스킬 + 예약 작업 |
| ChatGPT 무료 | Skills 생성 미지원 | 플러그인·앱은 별도 기능 | 가능하나 제한 있음 | 예약 작업 |
| Claude 무료 | 가능(Code execution 필요) | 커넥터·MCP 등 지원 범위 내 | 미지원 | 스킬 |

표 아래에 반드시 다음 주의문을 둔다.

> **무료 기준 안내**  
> 이 자료는 2026.10.06 개인 무료 계정을 중심으로 구성했다. 기능은 계정·지역·순차 배포에 따라 메뉴가 아직 보이지 않을 수 있으며, 제품 업데이트로 제공 범위가 바뀔 수 있다.

## 4. “예시보다 더 잘 쓰는 법” 핵심 박스
모든 페이지 하단 또는 1·5쪽의 강조 박스에 다음 취지를 반복하지 않는 범위에서 명확히 제시한다.

> **활동지의 예시는 시작점이다.**  
> 스킬의 목적·순서·출력 형식·금지 사항을 구체적으로 적고, 참고 문서·양식·좋은 결과물 예시를 함께 제공할수록 결과가 안정적이다. 또한 각 서비스에서 지원하는 범위 안에서 캘린더·메일·Drive·Figma·업무 시스템 등 다른 도구와 연결하거나 예약 작업과 스킬을 결합하면, 활동지의 단순 예시보다 더 실제적인 반복 업무 흐름으로 확장할 수 있다.

단, 특정 연결이 모든 무료 계정에서 가능하다고 오해하지 않도록 **“지원되는 범위 안에서”** 라는 표현을 유지한다.

- Figma 프레임: 각 794 × 1123 px
- PDF: 인쇄용 5페이지
- 실제 화면은 `SKILL,RESERVATION` 폴더의 캡처를 우선 사용한다.
- Figma 원본의 모든 텍스트·도형·이미지 프레임은 편집 가능한 레이어로 유지한다.

### 1쪽 — 무료 기준 기능 한눈에 보기
제목: **스킬·플러그인·예약 작업, 무엇이 다를까?**
- 상단: “2026.10.06 · 개인 무료 계정 중심” 라벨
- HOW / WITH WHAT / WHEN 3개 개념 카드
- Gemini / ChatGPT / Claude 무료 기능 비교표
- “왜 어떤 기능은 설명하지 않았나요?” 박스
- “예시보다 더 잘 쓰는 법” 박스

### 2쪽 — Gemini 스킬 만들기
제목: **Gemini에서 반복 업무를 스킬로 만들기**
- 소스 이미지: `제미나이 스킬 만들기1.png` ~ `4.png`
- 4단계:
  1. Skills 메뉴로 들어간다.
  2. 새 스킬 만들기 방식을 선택한다.
  3. 이름·설명·지침을 작성하고 필요한 참고 자료를 넣는다.
  4. 저장한 뒤 채팅에서 스킬을 불러 실제 업무에 사용한다.
- 조건 안내: 개인 계정, 18세 이상, Keep Activity 설정, 순차 배포
- 팁: `SKILL.md` 또는 지침 파일에 목적·사용 시점·절차·출력 형식·예시를 명확히 적는다.

### 3쪽 — Claude 스킬 만들고 사용하기
제목: **Claude에서 스킬을 만들고 반복 사용하기**
- 소스 이미지: `클로드 스킬 만들기1.png` ~ `4.png`
- 4단계:
  1. Customize → Skills로 이동한다.
  2. 새 스킬 만들기를 선택한다.
  3. `skill.md`가 포함된 스킬 폴더/압축파일을 업로드한다.
  4. 스킬을 켜고 실제 채팅에서 결과를 시험하며 지침을 보완한다.
- 무료 계정에서도 Skills를 사용할 수 있으나 Code execution이 켜져 있어야 한다.
- 좋은 스킬 구조: 목적 → 언제 쓸지 → 단계 → 출력 형식 → 예시 → 참고 파일

### 4쪽 — Gemini 예약 작업 만들기
제목: **Gemini에게 정기적으로 결과 받기**
- 소스 이미지: `제미나이 예약작업 만들기1.png` ~ `7.png`
- 1~6단계는 예약 생성·확인 흐름으로 배치하고, **7번 이미지는 실제 예약 결과가 도착한 장면을 큰 결과 카드로 배치**한다.
- 기본 예시 요청:
  “매주 월요일 아침, 이번 주 수업 준비 점검 항목을 5개로 정리해 알려줘.”
- **실제 응용 예시(7번 캡처)**:
  “특수학교 학생들을 대상으로 한 안전 포스터를 만들어줘. 포스터에 적힌 달은 만든 달이 아니라 다음 달이 표시되게 해줘. 관련 스킬도 적극 활용해줘.”
- 이 예시는 **예약 작업 + 구체적인 조건 + 관련 스킬 활용**을 결합하면 단순 알림을 넘어 정기적인 결과물 제작까지 확장할 수 있음을 보여준다.
- 무료 개인 계정에서도 Scheduled actions가 순차 제공된다.
- 무료 계정은 결과가 전달 시각보다 앞서 준비될 수 있으므로 빠르게 변하는 실시간 정보에는 적합하지 않을 수 있다.
- **Gemini Spark의 유료 예약 기능과 Gemini Chat의 Scheduled actions를 구분**해 설명한다.

### 5쪽 — ChatGPT 예약 작업 만들기
제목: **ChatGPT에서 반복 업무를 예약하기**
- 소스 이미지: `챗지피티 예약 작업 만들기1.png` ~ `6.png`
- 6단계를 실제 캡처 순서대로 배치한다.
- 무료 계정 핵심 제한:
  - 활성 작업 최대 3개
  - 일회성 또는 하루 1회 이하의 반복 작업
  - 무료에서는 “아침·오후·저녁”과 같은 유연한 시간창 중심
  - 정각·시간 단위 실행 등은 유료 플랜 범위가 될 수 있음
- 하단: **지침 + 첨부 자료 + 연결 + 반복** 확장 흐름
- “Claude 무료 플랜은 예약 작업을 지원하지 않아 이 활동지에서는 설명하지 않는다.”라고 명시한다.

## 6. 페이지 규격

## 9. 캡처 이미지 규칙
1. `SKILL,RESERVATION` 폴더의 실제 캡처를 우선 사용한다.
2. 캡처 순서는 파일 번호와 실제 작업 순서를 일치시킨다.
3. 한 화면에 필요한 정보가 많으면 과도하게 자르지 않는다.
4. 이미지 비율을 찌그러뜨리지 않고 FIT 방식으로 배치한다.
5. UI 위에는 긴 설명을 직접 겹치지 않는다.
6. 클릭 강조는 빨간 테두리·짧은 화살표·숫자 배지 정도만 사용한다.
7. 가상의 메뉴·버튼·경로를 만들어 넣지 않는다.
8. 이메일·개인정보·학교 내부 정보가 불필요하게 보이면 최소 범위만 마스킹한다.
9. 6개 화면 페이지에서도 “한눈에 봐야 하는 핵심 UI”가 읽히도록 캡처 크기를 우선 확보한다.

## 10. 단계 카드 구성
각 단계는 다음 순서를 유지한다.
1. 번호 배지
2. 행동 중심 제목
3. 실제 화면 캡처
4. 1~2줄 설명
5. 필요 시 □ 완료 체크

카드 제목은 “~을 확인한다”, “~을 누른다”, “~을 입력한다”처럼 사용자가 바로 행동할 수 있는 문장으로 작성한다.

## 11. 1쪽 비교표 표현 규칙
- 상태: **가능 / 제한 / 미지원 / 다른 방식**
- 색만으로 의미를 전달하지 않고 텍스트와 아이콘을 함께 쓴다.
- “미지원”은 제품 전체가 아니라 **이 활동지가 다루는 무료 플랜의 해당 기능**임을 분명히 한다.
- Gemini의 “순차 배포”는 가능 상태 옆에 작은 보조 라벨로 표시한다.

## 12. 좋은 스킬을 만드는 공통 프레임
스킬 제작 페이지에 다음 구조를 작은 체크 카드로 보여준다.
- 목적: 무엇을 반복하려는가
- 사용 시점: 언제 이 스킬을 불러야 하는가
- 입력: 어떤 자료를 받는가
- 절차: 어떤 순서로 판단·작성하는가
- 출력: 형식·분량·톤·파일 규격
- 금지: 하지 말아야 할 것
- 예시: 좋은 입력과 좋은 결과
- 참고 자료: 양식·문서·기존 결과물

## 13. 예약 작업 프롬프트 공통 프레임
예약 요청은 다음 요소가 있으면 결과가 더 안정적이다.
- 주기 또는 날짜
- 시간대 또는 시간창
- 매번 해야 할 작업
- 결과 형식
- 참고해야 할 자료
- 이전 결과와의 중복 방지 조건(필요할 때)

예:
“매주 월요일 아침, 이번 주 수업 준비에서 놓치기 쉬운 항목을 5개만 체크리스트로 정리해 알려줘. 지난주와 같은 표현은 반복하지 말고, 중요한 일정이 있다면 맨 위에 먼저 보여줘.”

## 14. 접근성
- 최소 본문 11.5 px 이상
- 본문 대비 4.5:1 이상 목표
- 빨강만으로 클릭 위치를 표현하지 않는다.
- 카드의 순서가 시각적으로도 왼쪽→오른쪽, 위→아래로 명확해야 한다.
- 인쇄 후 캡처 속 메뉴 글자가 식별 가능한지 확인한다.

## 18. 캡처와 설명을 연결하는 규칙
- **이미지 파일 번호를 설명 단계 번호와 1:1로 맞추지 않는다.** 실제 화면이 보여주는 의미와 사용 흐름을 우선한다.
- 하나의 설명 카드에 이미지 0개, 1개, 2개를 모두 허용한다.
  - 이미지 0개: 개념 비교, 주의 사항, 요금제 범위 설명
  - 이미지 1개: 한 화면에서 하나의 행동이 명확한 경우
  - 이미지 2개: 같은 행동의 전·후 화면, 서로 다른 예시, 결과와 수정 화면처럼 함께 봐야 이해되는 경우
- 동일한 예약 기능의 서로 다른 결과 예시는 **‘결과 예시’ 카드에 묶어** 보여줄 수 있다.
- 실제 결과물 이미지는 작은 단계 카드 안에 억지로 넣지 않고 **가로 전체 폭의 사례 카드**로 크게 보여준다.
- 각 설명은 “이 화면에서 무엇을 하는가 / 왜 필요한가”를 기준으로 작성하며, 파일명 자체를 사용자에게 설명하지 않는다.
- 단계 번호는 실제 학습 흐름에 따라 새로 매기며 원본 캡처 번호와 달라도 된다.

### 권장 묶음
- Gemini 스킬
  1. 메뉴 열기 + 「Gemini로 만들기」 선택: 스킬 1·2 이미지 2개
  2. 반복 업무 설명 + 생성된 스킬 확인: 스킬 3·4 이미지 2개
- Claude 스킬
  1. 사용자 지정 → Skills: 이미지 1개
  2. skill-creator에게 설명 → Skill 저장: 이미지 2·3 이미지 2개
  3. / 로 저장한 스킬 호출: 이미지 4개 중 1개
- Gemini 예약 작업
  1. 예약 관리자 열기 + 기본 예약 설정: 이미지 1·2
  2. 스킬 활용 조건 + 결과물 조건 고도화: 이미지 3·4
  3. 실행 결과 확인 + 기존 예약 지침 수정: 이미지 5·6
  4. 실제 정기 결과물 사례: 이미지 7을 크게 배치
- ChatGPT 예약 작업
  1. 예약 요청의 두 예시: 이미지 1·2
  2. 무료 계정의 시간 지정 제한 확인: 이미지 3
  3. 서로 다른 예약 결과 예시: 이미지 4·5
  4. 다음 실행 규칙 수정: 이미지 6

## 19. 1쪽 범위 안내
첫 페이지의 기능 지원 비교표 상단 또는 바로 아래에 다음 안내를 눈에 띄게 둔다.

> **이 표는 웹 채팅 기준이다.**  
> Gemini Chat, ChatGPT 웹 채팅, Claude 웹 채팅에서 직접 보이는 기능을 비교한다. Codex, AntiGravity, Claude Code 같은 개발형 에이전트 환경은 별도의 스킬·MCP·스크립트·자동화 기능을 사용할 수 있으므로, 이 표의 ‘미지원’을 그대로 적용하면 안 된다.

- “웹 채팅에서 미지원”과 “해당 회사의 모든 제품에서 미지원”을 같은 뜻으로 쓰지 않는다.
- 개발형 에이전트의 세부 기능은 제품 업데이트가 빠르므로 이 활동지에서는 구체적인 사용법까지 확장하지 않고 **범위가 다름**을 안내한다.
